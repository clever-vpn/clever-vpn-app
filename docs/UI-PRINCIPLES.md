# UI 原则（样板与可再品牌）

Last updated: 2026-10-28
Status: 生效（评审时按「必须」逐条卡；「推荐」仅供样板参考）

> 本文是 **clever-vpn-app 自己的设计文档**。跨仓库的写权限、`app.json` 字段语义、
> bridge 契约分别在 `clever-vpn-docs/docs/contracts/`，改那些要先动 docs 仓库。

## 0. 两种定制，一条边界

| | 初级定制（不用 Studio） | 高级定制（Studio） |
|---|---|---|
| 租户改什么 | `app.json` + `assets/icon.png` | `web/` 里的 HTML/CSS/JS |
| 能改变 | 名字、副标题、主色、CRM 连接、链接、图标/标记 | 布局、文案、组件、增删页面 |
| 门槛 | 改文件 → 构建 | 对话 / 工具 |

**判据**：某个值要进 `window.BRAND`，必须满足「改它就能生效，且完全不需要碰 CSS/HTML」。
它就是能力承诺，不是随手加个变量。

## 1. 必须（框架级，违反即坏）

| # | 规则 | 破了会怎样 |
|---|---|---|
| M1 | 品牌值（名字/主色/链接）从 `window.BRAND` 取，不写死在页面里 | `app.json.color` 同时决定图标、托盘、商店素材；写死了就是"图标紫色、界面蓝色" |
| M2 | 不引用任何外部资源（CDN / 字体 / 远程图片） | 离线崩；三端 WebView 还可能白屏 |
| M3 | 只通过 `bridge@1`（connect / disconnect / state / on）与壳交互 | 碰 kit 内部接口，换壳即废 |
| M4 | 守住 `web/` 限制：单文件 1 MB / 200 文件 / 深度 3 | CI 直接红，出不了包 |
| M5 | 任何页面都要有回退路径 | 用户卡死，只能杀进程 |
| M6 | 触控热区 ≥ 44×44 | 不是审美，是手指尺寸 |
| M7 | 外链（`links.*`、客服、官网、**第三方支付页**）用 `bridge.open(url)` 打开；壳没这个能力时退回 `target="_blank" rel="noopener"`。内部页面之间照常用相对链接 | 在 WebView 里加载第三方页面 = 没有地址栏、退不回来，桥和我们的 UI 一起被顶掉 |
| M8 | **线路图标不自己画**：只写 `line.icon` / `iconKind`，图从 `kit://line-icon/…` 取（`BRIDGE.md` §6）；壳不可用时用内置占位 | 图标集是 kit 的一部分；自己画一套，换 kit 版本或租户改线路就会对不上 |
| M9 | 行尾 `›` **只用于会打开新层级的行**。切换类操作（选线路、开关）不留 `›`，改用勾选标记（`role="radio"` + `aria-checked`）；且**切换后就地生效、不跳页** | `›` 是「点进去还有内容」的暗示；用在切换上等于骗用户点一次。跳页还会让误点无法撤回——留在原地，返回一次就是确认 |
| M10 | **连接中改参数要用户点头**：已连接时切换线路先弹确认（「切换到 X」「当前连接会断开。」→ 取消 / 切换），确认后先断开再切；未连接时随手切不弹窗，**连接中时直接忽略点击**（别打断半截状态） | bridge@1 没有原子「换线」，切换只能是断开 + 重连，中间会断网、还可能失败（设备超限/网络）。悄悄发生的话，用户只是看了下列表，连接就没了 |
| M11 | **选中态不只靠一个勾**：选中行给底色（`color-mix(brand 11%)`）+ 主色勾 + 字重 500 | 勾是 18px 的小图形，列表一长就得逐行找；底色让人一眼定位，勾负责确认「就是这条」 |
| M12 | **动 = 还没完成，静 = 完成了**：连接中才有持续动画（缺口弧旋转 + 心跳）；**已连接必须静止**，只在刚连上的一瞬放一圈确认波（0.9s，`forwards` 后归零）。只动 `transform`/`opacity`，不跑 JS 定时器，`prefers-reduced-motion` 时全关 | 转圈是「仍在加载」的通用信号。已连接还转，用户会以为没连上——这是把状态做反了。完成瞬间的一次性脉冲才是「好了」的正解，因为它会停 |
| M13 | **状态词三态平行**：未连接 / 连接中… / 已连接 —— 三个字同一形式（未·中·已），只有中间的瞬时态带省略号。**计时另起一行、同一中轴居中**跟在「已连接」下面，给数字一个主语 | 「连接中」和「已连接」字数不一，切换时会跳一下；而单独的 `01:02:35` 会被读成剩余时长/可用时长。状态词是最便宜的非颜色冗余，别为了少两个字把它删掉 |
| M14 | **根页面没有返回，推入页才有**：连接 / 线路 / 套餐 / 账户 四个 tab 根页面顶栏左侧不放返回，切页只走底部导航；推入页（设置→分流→地区、账户→兑换礼包）才有返回，而且返回的是**上一层**不是首页。**唯一例外**：匿名访问套餐时没有 tab 栏，那一页临时降级为推入页，要给返回 | tab 之间是平级的，一个「‹」会让人以为在往下钻，还占掉顶栏最宝贵的位置；反过来，没有 tab 栏的页面必须有出口，否则就是死胡同 |

## 2. 推荐（我们样板的做法，租户可整体替换）

| # | 做法 | 收益 |
|---|---|---|
| R1 | 颜色只出现在 CSS 变量区（8 个） | 换品牌一个值搞定 |
| R2 | 字号阶梯 6 档、间距 8pt 网格 | 不会越改越乱 |
| R3 | 每屏 < 150 行、扁平结构、语义类名 | AI 与租户都好改 |
| R4 | 每屏一个实心按钮 | 转化路径唯一 |
| R5 | 状态先于内容（顶部状态常驻） | 用户先知道"安不安全" |
| R6 | 不做灰按钮：不能用的功能要么不出现，要么点了给出口 | 未订阅时点哪都到套餐页 |
| R7 | 数字必须真；没有数据源的就不显示（如延迟 ms） | 不造假 |
| R8 | 不用插画/渐变/emoji 图标，图标内联 SVG | 三端一致、离线可用 |

## 3. 允许但不推荐

| 做法 | 代价（不是错误，是取舍） |
|---|---|
| 硬编码颜色/文案、不用 `_brand.js` | 放弃初级定制；且和上游分叉，升级要手工解冲突 |
| 改字号阶梯 / 8pt 网格 | 后续所有页面都要跟着改，AI 改动成本上升 |
| 加插画、做复杂动效 | 租户维护不了，AI 也改不动 |

## 4. 变量分两类

```
租户可改（app.json 出厂）
  --brand --bg --surface --text --dim --radius --gap --font

我们固定（设计系统）
  字号阶梯 / 间距档位 / 圆角档位 / 分隔线内缩 / 行高 / 触控尺寸
```

否则租户把字号改成 12px，整个产品就废了。

### 4.1 字号阶梯（固定，参考 Proton 的克制）

层级靠**字重 + 颜色**拉开，不靠巨大字号 —— 34px 那种 iOS 大标题在工具类 App 里嗓门太大。

| 变量 | 值 | 用途 |
|---|---|---|
| `--fs-display` | 30px / 600 | 品牌名（只有欢迎页用）|
| `--fs-title` | 26px / 600 | 认证页标题（登录 / 验证码）|
| `--fs-nav` | 17px / 600 | 内容页导航栏标题（居中、单行）|
| `--fs-h2` | 18px / 600 | 区块标题 / 主状态 |
| `--fs-body` | 16px / 400 | 正文、按钮、列表主文本 |
| `--fs-sub` | 14px / 400 | 次要说明、列表值 |
| `--fs-note` | 13px / 400 | 辅助、法律小字 |
| `--fs-tag` | 11px / 600 | 标签、徽标 |

### 4.2 标题对齐：跟着"页面在干什么"走

| 页面类型 | 对齐 | 理由 |
|---|---|---|
| 认证页（欢迎 / 登录 / 验证码）| **居中** | 用户还没进产品，整屏只做一件事：给出入口。标记 + 标题居中做视觉锚点，两边对称 |
| 内容页（位置 / 套餐 / 账户）| **导航栏标题居中** | 按 iOS 标准：左返回 / 中标题 / 右动作，见 §4.3 |

认证页里的**表单字段仍占满宽度、标签跟左边缘**——输入框是"块"，不是文字轴线，
所以"头部居中 + 字段满宽"不算打架；真正会打架的是"标题居中 + 短标签居中 + 输入框满宽"。

**垂直方向**：标题起点落在屏高 1/6 附近，内容靠上、页脚贴底；不要用 `100dvh` 做绝对居中
（键盘弹出时可视高度变化，整块会跳）。

### 4.3 内容页顶栏 = iOS 导航栏（不用大标题）

```
[ ‹ ]            位置            [ 动作 ]
─────────────────────────────────────
```

| 项 | 规定 |
|---|---|
| 高度 | **44pt**（不让大标题占两三行；信息密度不高的页面用不上）|
| 标题 | `--fs-nav` 17px / 600，**grid 固定占中间列**，单行、超长省略 |
| 左 | 返回上级或主页（`aria-label="返回"`，44×44 热区）；tab 根页面（如账户）不放返回 |
| 右 | 动作位（设置 / 搜索 / 更多）；**没动作就不放**，不要用空白占位符 |
| 吸顶 | `position: sticky` + 半透明背景 + 底部 1px 分隔线（iOS 的滚动手感）|
| 图标 | 内联 SVG，`stroke: currentColor`，20px |

> 标题用 `grid-template-columns: 44px minmax(0,1fr) 44px` 并显式 `grid-column: 2`：
> 这样**左/右按钮缺一个，标题也不会偏**（flex + space-between 做不到这点）。
>
> **主页（tab 根）**：标题就是**产品名**（`window.BRAND.name`），左右都空。
> 不要在顶栏放状态胶囊——「未连接 / 已连接」在页面中部大字那里，同一个信息说两遍，
> 顶栏那份还更弱（小字、无颜色权重）。等真有设置页了，右侧再放齿轮。

## 5. 模板化承诺

**凡进入官方模板的东西，必须只依赖 `app.json`（`window.BRAND`）+ `bridge@1` +
`app-crm.md` 的端点。** 不满足的不合入。

理由：官方模板必须是"任何人 fork 后只改两个文件就能上线"的状态，否则
「租户做模板 → 别人再基于它做品牌」这条路无从开始（本仓库 MIT，允许再分发）。

一个 UI 只要遵守第 1、2 节，它本身就是可再品牌的模板。

## 6. 欢迎页规格（供应商更换标识的主战场）

用户重装/换设备后看到的第一屏。它要能在一秒内回答"这是谁家的 App"，所以：

| 位置 | 内容 | 来源 |
|---|---|---|
| 右上角 | `?` → 客服/帮助 | `links.support`（没配就不渲染）|
| 中段 ① | 品牌标记，高度 = **屏高 1/6** | `logo`（缺省回落到 `icon`）|
| 中段 ② | 产品名 + 一句副标题 | `name` / `tagline` |
| 下段 ③ | 「开始使用」（实心）+「查看套餐价格」（次）| 固定文案 |
| 页脚 | 官网域名 + 条款/隐私 | `links.website` / `links.terms` / `links.privacy` |

硬规则：

1. **三段式**（标记 / 名称+副标题 / 操作），块与块之间必须靠留白分开，不能糊成一片。
2. 标记**不能贴顶**：中段在剥去头尾后的剩余空间里垂直居中。
3. 每一个来自 `app.json` 的值都必须**能空**：副标题空 → 不留空洞；`support`/`website` 空 → 整块不出现。
4. 页面里不写死任何品牌字。换一家租户，只改 `app.json` 这一屏就整张变。
5. 「?」和页脚域名都是**外链**：显式调 `bridge.open(url)`（见 M7 与 `BRIDGE.md` §5），不要在页面里用 `location.href`。
6. **垂直节奏（两个认证页共用）**：标记起点落在**屏高 1/6 附近**（欢迎页 ~21%、登录页 ~17%），内容靠上、页脚贴底。
   不要用 `100dvh` 做绝对居中 —— 键盘弹出时可视高度会变，整块会跳；屏幕特别高时居中还会把标题推到视线落点以下。

## 7. 登录页文案（越少越好）

用户是来用 VPN 的，不是来读说明的。这一屏只回答三个问题，其余全删：

| 位置 | 写什么 | 回答的问题 |
|---|---|---|
| 标题 | 「登录」 | 我在哪 |
| 输入框上方的标签 | 「邮箱」/「验证码」 | **这里填什么**（比任何说明句都短） |
| 占位符 | `example@email.com` / `000000` | 长什么样 |
| 主按钮 | 「发送验证码」→ 第二步「登录」 | 按了会发生什么 |
| 第二步标题 | 「输入验证码」 | 状态变了 |
| 第二步一行小字 | 已发送至 **xxx@…** | 刚才发生了什么 |
| 次要动作 | 重新发送（60 秒冷却）· **换个邮箱** | 没收到 / 写错了 |

**不写什么**（这几条是反复改出来的）：

- 不写「登录或注册」：那是在问用户"你有没有账号"，而他不需要回答。流程上 `/auth/verify`
  是唯一入口、邮箱不存在就建号（`app-crm.md` §2.2），所以只出现「登录」两字。
- **不解释机制**：不提密码、不提"会自动创建账号"、不提"6 位 / 10 分钟有效"。
  页面上不存在的概念不要先说出来（用户本来没想到密码，你一提他反而去找密码框）。
- 不写「验证并登录」：验证是手段，登录是目的。
- 不暴露账号是否存在（契约：`send-code` 响应恒定）—— 不能出现"该邮箱未注册，请先注册"。

**什么时候才允许加一句解释**：用户真的卡住时（客服工单、可用性测试里反复出现），
用**一行**解决，并且加在最相关的位置（例如输错码时提示"验证码已过期，重新发送一个"），
而不是在首屏堆说明。

保留「验证码」这个说法：中文用户对它的既有认知最强（手机验证码），比「登录码 / OTP / 一次性密码」都好懂。

## 8. 评审怎么用

逐条对照，不问"好不好看"，问三件事：

1. **换主色成立吗**（改一个变量，全站无死角）
2. **删一块会塌吗**（拿掉任意区块，剩下的仍是完整界面）
3. **加一屏便宜吗**（复制现有页改内容，不用碰共享 JS）
